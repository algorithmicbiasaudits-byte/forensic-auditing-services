HITL Security Overview

Human-in-the-Loop Compliance Audit Layer

ALS Consulting | April 2026

1

Encryption

Data at Rest

  • AES-256 encryption — All candidate data, audit logs, and compliance records encrypted at rest on Supabase (PostgreSQL)
  • Candidate identifiers hashed before storage — Names, emails, and SSNs never stored in plaintext
  • Database backups encrypted with same AES-256 standard

Data in Transit

  • TLS 1.3 — All API calls, webhook payloads, and client-server communication encrypted in transit
  • Enforced HTTPS across all endpoints (Render API, Netlify CDN, Auth0)
  • No fallback to HTTP; mixed-content requests blocked
What We Don't Claim: We do not offer end-to-end encryption or zero-knowledge architecture. HITL operates on a verified trust model where authorized compliance officers review candidate data — this by design requires decryption at the application layer for human analysis.
2

Authentication & Access Control

Role-Based Access Control (RBAC)

  • Auth0 multi-tenant RBAC — Each organization isolated; no cross-tenant data leakage
  • 3 Roles:
    • HR Lead: Run analyses, view own company's audit results
    • Compliance Officer: Review all audits, override low/medium risk flags, escalate high-risk
    • Executive Sponsor: View executive summary + high-risk escalations only (scoped elevation)

Access Elevation & Dual Authorization

  • Scoped elevation: Executives see candidate details only for HIGH-risk rejections requiring their override
  • Dual authorization required: Baseline configuration changes (audit rules, thresholds, comment policies) require sign-off from both Compliance Officer + Executive Sponsor
  • All access attempts logged with timestamp, user, and action taken

Multi-Factor Authentication (MFA)

Status: Auth0 supports MFA (TOTP, SMS, push notifications). MFA is available for enterprise clients on request; standard deployments use password + session-based authentication.
3

Data Handling & Retention

Anonymization & Hashing

  • Candidate identifiers hashed before storage — Internal system uses hashed IDs; plaintext identifiers encrypted and isolated
  • Audit reports display candidate reference numbers, not names (configurable by client preference)

Retention & Deletion

  • 90-day deletion post-termination: When a candidate is marked as hired/rejected/withdrawn, audit data auto-deletes after 90 days unless legal hold is requested
  • Legal holds respected indefinitely (e.g., discrimination claims, litigation)
  • Clients can request manual deletion at any time (subject to legal requirements)

GDPR & International Compliance

  • GDPR Article 6 (Lawful Basis): Processing is legitimate interest (bias detection) + contract (HITL service agreement)
  • GDPR Article 21 (Right to Object): Candidates can request their data be excluded from future audits
  • Data residency: EU candidate data stored on Supabase EU region (if requested)
  • Data Processing Addendum (DPA) available for enterprise customers

Audit Trail & Chain of Custody

  • All audit decisions logged with timestamp, user, and reasoning
  • Local encrypted backups maintained for 12 months for regulatory audits

Source Control

GitHub — Code repositories (no candidate data)

Database Access & API Security

  • No direct public database access — All queries routed through authenticated Render API with tenant verification
  • Webhook endpoint validation: All incoming webhooks must include valid API key + tenant signature (HMAC-SHA256)
  • Rate limiting: API endpoints rate-limited by tenant (burst: 100 req/sec; sustained: 1000 req/hour)
  • SQL injection protection via parameterized queries (ORM enforcement)

Network Security

  • All inbound traffic routed through Netlify edge with bot detection
  • Outbound requests from Render use fixed IP ranges (Stripe, Resend, Auth0 whitelists)
  • VPC isolation: Internal services do not expose ports to public internet

Offline Backups & Chain of Custody

Offline Backup: ALS Consulting maintains AES-256 encrypted local backups of immutable audit trails and decision logs at our Winston-Salem, NC facility. This provides physical custody for chain-of-custody requirements and disaster recovery independent of cloud providers. Retrieval requires dual authorization.

Anthropic Claude API — Disclosure & Data Handling

Anthropic (Claude API) Disclosure: F.A.S. uses Anthropic's Claude API as a structured classification engine — not a generative decision-maker. The 7 compliance lanes are deterministic rule-based frameworks with fixed thresholds. Claude API parses rejection payloads and maps them to these pre-defined categories. The final risk score, blocking decision, and escalation logic are determined by ALS Consulting's proprietary code. All Claude outputs are advisory; every flagged decision requires human review by a designated compliance officer before it binds. API inputs are processed in real-time and not retained by Anthropic beyond the session. ALS Consulting is actively negotiating a Data Processing Agreement (DPA) with Anthropic.

Incident Response

Detection & Containment

  • Continuous monitoring: Render, Supabase, and Auth0 configured with real-time alerts for unauthorized access, API abuse, or data anomalies
  • Incident classification: Low (system warning), Medium (potential access anomaly), High (confirmed data exposure)
  • Upon detection of High-severity incident, immediate containment steps:
    • Isolate affected systems
    • Preserve logs for forensic analysis
    • Revoke compromised credentials
    • Block affected API endpoints

Notification Protocol

  • 72-hour breach notification: Affected organizations notified within 72 hours of confirmed data exposure (incident date, scope, remediation steps)
  • Notification sent to designated security contacts via email + phone if available
  • Law enforcement notification: Coordinated with customers' legal teams; ALS Consulting will cooperate with investigations

Remediation & Recovery

  • Post-incident: Full forensic review of logs, access patterns, and system configurations
  • Public incident summary posted within 5 business days (if impact >50 users)
  • Remediation status shared with affected customers bi-weekly until resolved
